# `reg-auto-req-analysis` 技能工具化改造方案

## 一、现状问题

### 1.1 Agent 不遵守 SKILL.md 约束

`auto-analysis-agent` 目前 `tool_groups: [bash]`，Agent 拥有完整的 Shell 权限。虽然 SKILL.md 写了"禁止手写脚本"，但 Agent 仍然：

| 违规行为 | 日志证据 | 后果 |
|---------|---------|------|
| `python3 -c "import redis; r.setex(...)"` 手写 Redis | 236942 任务 12:24:48 | Redis 数据不完整（string 类型，缺 checklist 结构） |
| `pip install redis` 装包 | 236942 任务 12:24:58 | 沙箱尝试安装未授权包 |
| `inspect.getsource()` 读 Python 源码 | 235854 任务多处 | 浪费大量 token，任务超时 |
| 项目名猜错/遍历 | 237152 任务 | 空转，未产生结果 |

### 1.2 根因

**不是 SKILL.md 写得不够好，而是 `bash` 工具本身权限过大。** 就像给人一把瑞士军刀，然后告诉他"只准开瓶盖"——理论上可以，实际做不到。

SKILL.md 已经写了：
- 第 24-26 行：命令与脚本纪律（先查 COMMANDS.md，别手写）
- 第 30-37 行：绝对禁止读 Python 源码
- 第 39-52 行：硬约束禁止交互

但 Agent 拥有 `bash` = 拥有一切能力，SKILL.md 只是一段文字建议，Agent 可以选择不遵守。

---

## 二、改造方案：把脚本注册成独立工具

### 2.1 核心思路

去掉 `bash`，将 5 个脚本的 13 个子命令注册为 DeerFlow 工具（Tool）。Agent 只能调这些工具，不能执行任意 Shell 命令。

```
改造前：tool_groups: [bash]          → Agent 什么都能做
改造后：tool_groups: [file:read, file:write, tfs-tools] → Agent 只能调特定工具
```

### 2.2 现有工具组（可直接用）

来自 `config.yaml` 的内置工具：

**`file:read` 组：**
| 工具 | 用途 |
|------|------|
| `read_file` | 读 SKILL.md、config/qc-rules.md、references/*.md 等 |
| `ls` | 目录浏览 |
| `grep` | 关键词搜索（产品 wiki 检索） |
| `glob` | 文件名模式匹配 |

**`file:write` 组：**
| 工具 | 用途 |
|------|------|
| `write_file` | 写入执行计划 JSON、变更方案 Markdown、测试日志 |

> ❌ 缺 `mkdir -p`：没有创建目录的工具。需要在新工具中内置。

### 2.4 工具函数实现

在 `skills/reg-auto-req-analysis/_lib/tfs/tools.py` 中实现：

```python
from langchain.tools import tool
import subprocess, os, json

SKILL_ROOT = "/mnt/skills/public/reg-auto-req-analysis"

def _run_script(script: str, *args: str) -> str:
    """运行技能脚本并返回 stdout"""
    script_path = f"{SKILL_ROOT}/_lib/tfs/{script}"
    cmd = ["python3", script_path] + list(args)
    result = subprocess.run(cmd, capture_output=True, text=True, timeout=300)
    if result.returncode != 0:
        return f"Error: {result.stderr}"
    return result.stdout

@tool("tfs_fetch", parse_docstring=True)
def tfs_fetch(work_item_id: int, collection: str = "WN_Data_Platform",
              pat: str = "") -> str:
    """获取 TFS 工作项。首次调用时自动创建运行目录。
    Args:
        work_item_id: TFS 工作项 ID
        collection: TFS 集合名称
        pat: TFS Personal Access Token（可选，有缺省配置）
    """
    # 自动创建运行目录
    run_dir = f"/mnt/user-data/workspace/过程文件/{work_item_id}"
    os.makedirs(f"{run_dir}/附件", exist_ok=True)
    os.makedirs(f"{run_dir}/附件解析", exist_ok=True)

    args = ["fetch", str(work_item_id)]
    if collection:
        args += ["--collection", collection]
    return _run_script("tfs_client.py", *args)

@tool("pipeline_validate", parse_docstring=True)
def pipeline_validate(plan_path: str) -> str:
    """校验执行计划 JSON 的完整性和合规性。
    Args:
        plan_path: 执行计划 JSON 的完整路径
    """
    return _run_script("pipeline.py", "validate", "--plan", plan_path)

# ... 其他工具类似
```

### 2.5 Agent 配置变更

```yaml
# agents/auto-analysis-agent/config.yaml
name: auto-analysis-agent
description: Requirement evaluation and requirement document generation with TFS write-back.
skills:
  - reg-auto-req-analysis
tool_groups:
  - file:read       # 读规则文件、浏览目录、搜索
  - file:write      # 写执行计划、变更方案
  - tfs-tools       # 13 个子命令，覆盖全部 5 个脚本
recursion_limit: 500
```

## 三、效果对比

| 行为 | 改造前 (`bash`) | 改造后 (`file:read` + `file:write` + `tfs-tools`) |
|------|----------------|--------------------------------------------------|
| `python3 -c "import redis"` | ✅ 可以 | ❌ 调不了 |
| `pip install` | ✅ 可以 | ❌ 调不了 |
| `inspect.getsource()` 读源码 | ✅ 可以 | ❌ 只能 `read_file` 读 .md |
| `cat config/qc-rules.md` | ✅ `cat` | ✅ `read_file` |
| `mkdir -p 过程文件/` | ✅ `mkdir` | ✅ `tfs_fetch` 自动创建 |
| `python3 tfs_client.py fetch` | ✅ `bash` | ✅ `tfs_fetch` 工具 |
| `python3 pipeline.py validate` | ✅ `bash` | ✅ `pipeline_validate` 工具 |
| 写执行计划 JSON | ✅ `echo >` | ✅ `write_file` |
| 搜索 wiki | ✅ `grep` | ✅ `grep`（file:read 组） |
