# 高风险清单（6 类 · 中心负责人签字担责）

> **共享规则**：质控阶段（早筛）和分析阶段（定性）**共用本文件**作为 6 类高风险的单一权威来源。中心负责人维护；改这里，两处自动生效，不漂移。
>
> 命中**任一类**即算高风险。判定方式：扫标题/描述/分析者描述/涉及对象/变更点，**关键词或语义命中任一即算**（不只靠关键词，语义上属于该类也算）。

| # | 高风险类 | 关键词 / 范围 |
|---|---|---|
| ① | **患者安全** | 临床决策、用药路径、诊疗规则、医嘱、危急值 |
| ② | **支付结算** | 医保结算、费用计算、财务过账 |
| ③ | **数据迁移** | 跨院区、历史转换、不可逆写入 |
| ④ | **首次发布新模块** | 无历史基线的新模块首次上线 |
| ⑤ | **合规强监管** | 电子病历归档、三级等保、审计日志 |
| ⑥ | **架构级改动** | 跨系统接口、公共中间件、数据库 schema |

## 各阶段怎么用这份清单（B 方案：质控早筛 + 分析定性）

- **质控阶段·早筛**（spec 清晰度二分）：从**需求本身**（标题/描述）能判出高风险的（多见于 ①②⑤，关键词明显），命中后**按 spec 清晰度分**：高风险 + **spec 清晰** → `PASS` 进分析（由分析阶段 `MANUAL-REVIEW` + `PM-AI-STOP-AUTO` 兜底人工复核，质控不挡回）；高风险 + **spec 不清** → `PM-AI-QC-NEED-REVIEW`（交产品确认业务规则后重跑）、停止。质控早筛**不打 STOP-AUTO**（分析阶段产物）。从需求看不出的（多见于 ③④⑥，要等变更方案）→ 留给分析。
- **分析（auto-req-analysis）·定性**：基于**变更方案**做定性判定，命中 → `MANUAL-REVIEW` + `PM-AI-STOP-AUTO`。这里能兜住质控早筛看不出的（架构级 / 数据迁移 / 不可逆写入等）。

> **边界**：本清单只决定**路由 + 打标签**；`PM-AI-STOP-AUTO` 对下游 auto-dev 的"禁止自动开发"效果由下游研发链路实现，不在本 skill 范围。
> **与《汇报版》区别**：不复用其 7 类点火逻辑（已出范围）；这 6 类只作为路由/`STOP-AUTO` 的触发规则。
