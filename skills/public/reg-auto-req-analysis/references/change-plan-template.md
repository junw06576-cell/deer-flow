# 变更方案文档模板（PM/业务视角）

> 给 `auto-req-analysis` 用。产出 `变更方案_<id>_<run_id>.md`（整体方案 §4.9「自动生成变更方案资料」），完整 Markdown 上传为 TFS 附件；执行器只提取“## 三、分析者描述”并渲染为 HTML，写入【详细信息】的【分析者描述】区段。
> **PM/业务视角**：业务场景/规则/验收/范围为主。分析者描述用“菜单路径 + 操作路径”帮助研发理解业务入口；**代码级定位（仓库/类/方法/接口/调用链/Mapper/推断出的表字段）是内部佐证，不进产物正文**。工作项或已解析附件明确给出的业务字段、参数和数据规则可以写入。按 `config/analysis-rules.md` §4 + `_lib/module-location-recipe.md` 内部跑，结果落 `kb.findings`（喂 verdict/查重/高风险）。
> 内容严格基于 `fetch` 返回的工作项；不需要 PM 决策的临时前提、以及**呈现类**业务缺口（格式/文案/顺序/空值显示等）的合理默认可陈述为假设（见 `confidence-heuristic.md` 缺口分流）。**正确性类**缺失信息（影响金额取数/计算精度/业务规则/异常处置/合规/权限/验收）必须写入计划 `analysis_gaps`，不编造、也不用默认兜。

---

`变更方案_<id>_<run_id>.md`（例：`变更方案_228549_20260720_abc12345.md`）

## 填写规范
- **取值严格自 fetch**：标题/状态/产品/描述等不编。
- **路径必填且唯一**：紧跟需求类别行，固定包含“菜单路径”和“操作路径”。菜单路径使用业务菜单层级，操作路径使用 `→` 串联业务步骤；不得写仓库、工程路径、类、方法、接口、Mapper、表或字段名。无法确认的部分写“未确认”，不编造。
- **先写分析者描述（三）**：读 `analysis-description-writing-rules.md` 选择一项或多项类别，使用业务锚点填齐必需维度。简单事项简短准确；复杂或跨系统事项再展开流程、范围、风险和验收。不得只复述标题、写模板占位符或空泛话术；**且须对需求方方案/文案做业务合理性判断——合理沿用、不合理则优化并简述理由（见 `analysis-description-writing-rules.md`「业务合理性判断」）**。此节必须保持受控 Markdown 行格式；不写 HTML，执行器负责安全渲染。
- **先完成闭环（二）再写类别（三）**：类别、业务规则、变更点、风险和验收必须与闭环的目标状态、保持不变项和成功衡量一致；正文不展示证据来源或技术定位。`evidence-loop-v1` 的五个三级标题和必填字段必须各出现一次且非空，不能用候选实现、未确认根因或“按现有逻辑”代替业务结论。
- **查询能力分级（三）**：简单查询仅在“单个条件调整 + 既有结果列复用 + 不改计算/写入/状态/权限/关联视图”同时满足时使用 `existing-query-simple`，用三项说明改动、规则和不涉及范围；否则使用 `existing-query-adjustment`，查询条件、筛选/匹配规则、结果字段与展示、空值/无结果、关联详情/导出/打印、权限/脱敏和验收场景必须成套分析。两类均须先用工作项、已解析附件或已核实页面确定结果列表是否已有同一业务标识字段：已有则复用，只有已证实缺失才新增；禁止从新增查询条件臆测结果列缺失。取数口径、匹配方式、权限/脱敏或关联视图范围不清时回退质控，禁止用“按现有逻辑”掩盖。
- **PM 视角，禁堆技术定位**：正文**不写**仓库、类、方法、接口、调用链、Mapper 或图谱推断的表字段；工作项或附件明确的业务字段、参数、统计规则可以写。三态/置信度及全部技术定位落 `kb.findings`（内部）。
- **变更点清单（四）业务级 + 可枚举**：AUTO 改动量依据；枚举不出 → MANUAL。
- **假设 vs 待确认（三向分流）**：不影响 PM 业务决策的临时前提 → §六**假设**；**呈现类**业务缺口（格式/文案/顺序/空值等，错了只是体验）→ §六**合理默认 + 适用边界**，不进 `analysis_gaps`、不阻断 AUTO；**正确性类**缺失信息（金额取数/计算精度/业务规则/异常处置/合规/权限/验收）→ 计划 `analysis_gaps`，非空时生成 `manual-followup`。清单不重复自动标签、终局或高风险定性，见 `manual-review-template.md`。
- **AUTO 白名单（七）**：判 AUTO 必须逐项证明全部变更只属于 `field-ui-copy`、`unit-test-completion`、`config-enum-adjustment`；任一未列出改动 → MANUAL。
- **分析结论（七）**与 skill 最终打的标签一致。
