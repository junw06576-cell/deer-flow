# 需求分析待确认项模板

> **仅用于历史计划回放兼容。** 新计划固定 `confirmation_policy=qc-single-batch-v1`，PM 可回答的业务缺口全部在 QC checklist 一次性确认，分析计划 `analysis_gaps=[]`，不得生成本附件。历史 `analysis_gaps` 非空计划仍按本模板校验。

```markdown
# 需求分析待确认项 · TFS <id> <标题>

<!-- auto-req-run:<run_id> -->

- **工作项**：<id>
- **责任方**：PM
- **生成时间（UTC）**：<ts>

## 需要确认的需求分析信息
> 仅列 PM 可补齐、且影响业务规则、范围、计算/精度、异常处置或验收的业务信息。标签、终局、高风险定性、是否自动开发和状态流转均为系统自动处理，不写入本清单。

### <gap-id> · <业务主题>
<!-- analysis-gap:<gap-id> -->
- **缺失信息**：<当前未从工作项、已解析附件或已证实业务证据获得的信息>
- **对分析/验收的影响**：<若不补齐会影响的规则、范围、计算、异常处置或验收>
- **需确认的问题**：<PM 可直接回答的业务问题>
- **候选口径**：<一个或多个可选业务口径>
- **允许自由补充**：<是 | 否>

## 后续动作

PM 补充上述信息后重新运行分析；标签、风险判定和状态流转由系统流程处理，本 skill 不在此附件中重复确认。
```

## 填写规范

- 每个 `analysis_gaps` 项必须在正文中有同名 `<!-- analysis-gap:<id> -->` 标记，且按模板字段完整展开。
- 仅列可由 PM 补齐的业务分析缺口；不得写技术实现、代码定位、表字段或 Mapper。
- 现有实现、相似能力、调用路径或方案取舍的**证据定位失败**写计划 `evidence_gaps`，仅入运行审计并交研发或知识库治理；不得借用本清单向 PM 追问技术证据。
- **呈现类**业务缺口（格式/文案/顺序/空值显示等）用变更方案 §六合理默认兜底，**不进本清单**；本清单只收**正确性类**缺口（金额取数/计算精度/业务规则/异常处置/合规/权限/验收）。spec 类问题（落地层/范围/一致性）归质控，也不进本清单。
- 不得出现自动标签、AUTO/MANUAL 判定、高风险定性、禁止自动开发或状态流转确认。
- 不需要 PM 决策的临时分析前提可写变更方案 §七“假设”；会影响业务结论的缺失信息必须进本清单。
