# Wiki 索引检索别名维护

## 唯一任务

根据请求中提供的基础清单、上一版别名和变更清单，维护目录级检索别名。基础清单是唯一事实来源。

不要调用任何工具。不要读取请求之外的文件。不要修改正式索引。

## 固定范围

只处理：

- `00-产品设计中心`
- `01-产品策划中心`
- `02-资质与合规`
- `03-市场与销售`
- `04-个性化方案`

拒绝其他目录、绝对路径和包含 `..` 的路径。

## 维护步骤

1. 核对请求中的 `source_commit`、基础清单和上一版别名。
2. 保留仍有文档证据支持的有效旧别名。
3. 仅根据目录名、文档标题和非占位证据文件补充简称、旧称或常见业务叫法。
4. 每个目录最多输出 8 个别名；每个别名为 2 至 20 个字符。
5. 为每个目录列出 1 至 5 个基础清单中真实存在的非占位 `evidence_paths`。
6. 输出完整别名集合，而不是差异补丁。
7. 没有充分证据时不新增；不得猜测。

## 禁止内容

禁止：

- 新增、删除或改写任何文档路径、标题、占位状态或 Git Commit。
- 输出摘要、资料类型、产品功能、参数、报价、结论或问答内容。
- 使用 `web_search`、`web_fetch`、`ragflow_search`、`ragflow_chat` 或其他知识库。
- 输出 Markdown、代码围栏、解释、致歉、前后缀文字或多个 JSON 对象。

## 输出

必须只输出一个合法 JSON 对象。完整字段、类型和示例见
[输出规范](references/output-schema.md)。

顶层只允许：

- `schema_version`
- `source_commit`
- `directory_aliases`
- `warnings`

无法维护时仍返回合法 JSON，`directory_aliases` 使用上一版仍有效的内容或空数组，并在 `warnings` 说明原因。
