## 工作流程

严格按以下顺序执行。每步都必须完成后再进入下一步。

### Step 1: 确认产品范围

用户请求中可能已明确指定产品，也可能只说"出个硬件资源清单"。

- 已明确 → 直接进入 Step 2
- 未明确 → 用 question 工具让用户勾选

**WXP 运维平台为所有项目必选公共组件，不询问，默认包含。**

可选产品（多选）：
1. 基层医疗信息系统V5.6
2. 智慧公卫系统（含基本公卫/家医签约/健康管理，按组合自动匹配变体）
3. 健康体检
4. 区域平台V6.0

### Step 2: 收集项目信息

| 参数 | 说明 |
|---|---|
| 项目名称 | 用户指定 |
| 建设范围 | 项目覆盖区域 |
| 信创/非信创 | 决定源文件选择 |

### Step 3: 收集档位参数（只问选了的产品）

用一次 question 调用，尽量合并问题。

| 如果选了 | 追问内容 | 用于 |
|---|---|---|
| 基层医疗 | 日门诊量（3选1：≤5000 / 5000-10000 / 10000-15000） | 基层医疗档位 |
| 智慧公卫 | 常住人口 + 需要哪些子系统（基本公卫/签约/健康管理）→ 自动匹配变体 | 公卫档位+变体 |
| 健康体检 | 常住人口 | 公卫类档位（3档） |
| 区域平台 | 常住人口 + 全量 or 套组 | 区域平台档位（3档）+ 配置类型 |

**档位确定规则：**
- 基层医疗按日门诊量定档
- 智慧公卫/健康体检/区域平台按常住人口统一分档
- 基层医疗档位划分：≤5000 / 5000-10000 / 10000-15000（另有非标最小档：日门诊量≤1000且机构数量≤3，仅当用户明确要求最小资源清单时提供，否则≤1000按第1档处理）
- 公卫类档位划分：≤100万 / 100-300万 / 300-700万
- 区域平台档位划分：≤100万 / 100-300万 / 300万+

**区域平台配置选项（如选了区域平台）：**
- 全量清单（17项服务明细）
- 基础+EHR+BI（16项，无检查检验/双向转诊）
- 检查检验互认（15项）
- 双向转诊（5项，合并行写法）
- 健康档案共享（14项）
- 综合监管（13项）

**智慧公卫变体选择规则（如选了智慧公卫）：**
根据用户需要的子系统自动匹配变体名称：

| 用户需要的子系统 | variant 值 |
|---|---|
| 仅基本公卫 | `基本公卫` |
| 仅家医签约 | `签约` |
| 仅健康管理 | `健康管理` |
| 基本公卫 + 家医签约 | `基本公卫+签约` |
| 基本公卫 + 家医签约 + 健康管理 | `基本公卫+签约+健康管理` |

> 注意：签约+健康管理（不含基本公卫）无独立变体，使用 `基本公卫+签约+健康管理`

### Step 4: 生成 Excel

将收集到的参数写入 JSON 配置文件，然后运行脚本生成 Excel。

**脚本路径**：`scripts/generate_excel.py`

**配置文件格式**（写入临时文件后传给脚本）：
```json
{
  "project_name": "项目名称",
  "scope": "建设范围",
  "population": 100,
  "xinchuang": true,
  "products": {
    "基层医疗": {"outpatient": 8000},
    "智慧公卫": {"variant": "基本公卫+签约"},
    "区域平台": {"combo": "全量清单"}
  }
}
```

**products 键**：基层医疗、智慧公卫、健康体检、区域平台
**智慧公卫 variant 值**：基本公卫 | 签约 | 健康管理 | 基本公卫+签约 | 基本公卫+签约+健康管理
**区域平台 combo 值**：全量清单 | 基础EHR+BI | 检查检验互认 | 双向转诊 | 健康档案共享 | 综合监管
**基层医疗可选参数**：`"minimal": true` 启用非标最小档（日门诊量≤1000且机构数量≤3），仅在用户明确要求时使用。**注意：当前数据源（平铺 md）不含非标最小档，请求时脚本会报错——需先在源 Excel 中补充该档位并重新入库**

**运行命令**（--source-dir 为数据源，支持两种形式）：
```bash
# 标准方式：内网 HTTP 数据源（任何内网机器/192容器通用，永远是知识库最新版）
python3 scripts/generate_excel.py --config config.json \
  --source-dir http://172.16.0.192:8765/wiki/01-产品策划中心/11-硬件资源源数据/区域卫生产品推荐硬件资源清单.md

# 备选：本地目录（知识库 clone 内的数据目录或本地转换的平铺 md 目录）
python3 scripts/generate_excel.py --config config.json --source-dir <本地md目录>
```

> 数据服务由 172.16.0.192 上的静态文件服务提供（指向每日 git 同步的发布目录，cron watchdog 自动保活）。公司内网即可访问，无需挂载或凭据。

**输出路径规则**（无需手动指定 --output）：
- 在当前工作目录下自动创建 `项目名称/` 文件夹
- Excel 输出到 `项目名称/项目名称_硬件资源清单.xlsx`

脚本自动处理：
- 自动创建项目文件夹（以 project_name 命名）
- 从数据源（URL 或本地）按 `## {sheet名}`（含信创/非信创标识）+ 章节标题（档位/变体/套组）读取源数据
- WXP 数据同样来自数据源「WXP必选」sheet
- 公共组件共享（公卫类≥2时只在基本公卫sheet保留）
- 硬件负载行F-J清空
- SUMPRODUCT合计公式
- 跨sheet引用的项目汇总
- 合并单元格、样式、数字格式

**数据源说明**：唯一源为 `区域卫生产品推荐硬件资源清单.xlsx`（9 sheet：WXP必选 + 4产品×信创/非信创），经知识库 reg-kb-ingest 通用流程转为固定名笔记 `01-产品策划中心/11-硬件资源源数据/区域卫生产品推荐硬件资源清单.md`（文件名固定不变，版本信息在标题与 log，保证 URL 永久有效）。更新数据 = 修改源 Excel → 投喂入库 → 192 服务器每日 03:00 自动同步 → HTTP 数据源自动更新，技能零改动。源 Excel 需保持：产品 sheet 名带（信创）/（非信创）、WXP必选共用一份、章节标题行（档位/变体/套组）、17 列表头结构。

### Step 5: 验证输出

生成后确认：
- Sheet 数量和名称正确
- 合计公式覆盖正确数据范围
- 跨 sheet 引用列映射正确（B→F, C→G, D→H, E→I, F→J）
- 公共组件不重复
- 硬件负载行无数值
- 数值与源文件精确匹配
