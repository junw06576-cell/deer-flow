# reg-auto-req-analysis-offline 执行效率问题与优化建议

> 依据：2026-09-07 两次 run 实测（run_20260907_013459 撞墙中断、run_20260907_023853 全程 27.5 分钟）+ Gateway/沙箱源码核对 + thread state 消息级复盘。
>
> **结论先行**：当前 QC 终局 run 全程约 27.5 分钟，其中 36% 是沙箱撞墙纯浪费；实际干活的 13 分钟里约 60% 是可消除的结构性开销。全部优化落地后预期压缩至 **3-5 分钟**。

## 一、实测基线（工作项 245706，第 2 次 run）

| 阶段 | 时间 | 耗时 | 性质 |
|---|---|---|---|
| run 触发 | 10:31:11 | - | agent 启动，读 SKILL.md（prompt 注入，免沙箱） |
| 撞墙循环 | 10:31-10:38 | **7.5 min** | 10 次"沙箱并发上限(3)"拒绝，LLM 层重试空转 |
| 实际干活 | 10:38:53-10:52 | **13 min** | 21+ 轮工具调用，每轮 LLM 30-60 秒 |

撞墙发生在**干活过程中**（第一次真正执行命令时），不是前置排队。每撞一次都是一轮完整模型调用，生成内容全是"沙箱并发仍受限，继续等待"类空话。

## 三、改进建议（按 ROI 排序）

### P0 配置与操作（今天可做，不动 skill）

1. **沙箱扩容**：`config.yaml` sandbox 段加 `replicas: 6` + `idle_timeout: 1200`，重启 gateway。⚠️ 重启会杀当前所有 run，只在批次空闲时执行。
2. **重分析前删旧 thread**：`DELETE /api/threads/{collection}-{id}` 清目录+checkpoint+元数据，上下文归零（run 台账/过程文件/Redis 键不受影响，属可接受残留）。
3. **调度侧限流**：TFS-BUDDY 批量触发时同 worker 并发 run 数 ≤ 沙箱上限，超量在调度侧排队，别让 agent 自己撞墙。

> 预期：消除 A1/A2/A3，撞墙 7.5 min → 0。

### P1 skill 文档层（一次编辑 SKILL.md，下个版本生效）

4. **SKILL.md 开头加「常量速查」段**：终局→标签映射、结果 16 键、知识五键、清单条目结构、流转五键、run_id 格式、产物目录约定——开局免读 6-8 份契约，直奔质控判定。
5. **产物写入 SOP 统一**：heredoc 写完直接接 `python3 json.load` 校验 + `check_deliverables.py` 自检（一条命令 `&&` 串联），禁止 cat 全文回读（回显截断必触发二次验证）。
6. **校验与写入合并轮次**：写入+校验+自检一条命令完成，砍独立回读轮次。

> 预期：砍 8-12 轮，干活 13 min → 8 min。

### P2 结构改造（skill 半执行器化）

7. **preflight 校验脚本**：一条命令输出载荷全部契约问题（结构/路由/时效/附件对账一次性跑完），替代 LLM 逐文件读规则再人工比对。路由解析已有 `build_menu_business_index.py resolve-route`，补齐其余校验即可。
8. **产物骨架脚本**：`generate_deliverable_scaffold.py` 生成三产物骨架（含全部必填键与格式），LLM 只填业务内容（清单问题文本、知识摘要、结论）——heredoc 手搓 3.8KB JSON 的生成时间与失真风险同时消除。
9. **输入载荷文件化**：TFS-BUDDY 把载荷同时落为 sandbox 可见文件（如挂在 /mnt/user-data/inputs/），agent 直接 cp 保真，替代手抄转写。需 TFS-BUDDY 侧配合改一处。

> 预期：砍 6-8 轮 + 根治转写失真，干活 → 5 min。

### P3 长期（执行器化 + 业务闭环）

10. **offline skill 对齐生产版执行器模式**：QC 判定矩阵、产物投影、结构自检全部脚本化，LLM 只产出两样东西——质控结论、待确认问题文本。参照生产版 `pipeline.py` 模式。
11. **业务拍板：批量注册产品路由**：RDA-02/RDA-03/RSA-10/RSA-11 一次性注册（agent 已在 q-product-route 候选答案 5 给出此方案），消除 D1 全部阻断——这是**业务收益最大**的一项，此前 6+ 个工作项全部因此止步。
12. **载荷源头修复**：TFS-BUDDY 下载真实报告文件（当前存的是下载失败的错误响应体）；迭代日历接入载荷组装。

## 五、风险与注意事项

- 改 config 须重启 gateway，**会杀当前所有 run**，只在批次空闲时做。
- 删 thread 三样（目录+checkpoint+元数据），不删 run 台账/过程文件/Redis 质控计划键——如需彻底清残留见《192服务器DeerFlow运维手册》。
- SKILL.md 改动经 TFS 仓库流程（`scripts/pull-reg-auto-req-analysis.sh`）或本地 skills 目录同步，改完重启 gateway 生效（进程内有配置缓存）。
- 所有 P1/P2 改动需过 `check_deliverables.py` 结构自检 + 一次真实 run 冒烟验证后再批量启用。
