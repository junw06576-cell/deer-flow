调用方式

TFS-BUDDY 工作流平台作为调用方，向 FastAPI 服务发送 HTTP 请求。所有请求通过 X-API-Key 头认证。

可用接口
POST/api/v1/evaluation/start
POST/api/v1/evaluation/continue
POST/api/v1/generation/start （仅重试）
入参（所有接口统一）
参数类型必填说明
collection_namestring是TFS 集合名称，如 WN_Data_Platform
work_item_idint是TFS 工作项 ID
tfs_patstring是TFS Personal Access Token
tfs_projectstring是TFS 项目名称
answersarray仅 continue用户答案列表 [{question_id, answer}]
关键：collection_name + work_item_id 用于构造 thread_id（"{collection_name}-{work_item_id}"），TFS-BUDDY 无需存储 Thread ID，每次直接算出。
2
FastAPI 服务封装层
纯透传 不做业务逻辑
职责

FastAPI 不做 TFS 回写、不做 文档解析等业务逻辑。只做三件事：

  • 构造 thread_id，透传请求至 DeerFlow
  • 调用 DeerFlow LangGraph API（同步阻塞，600s 超时）
  • 解析 Skill 输出中的标记（<tfs_result> / JSON），透传至响应

TFS-BUDDY 只需一个循环：发需求 → 收问题 → 答问题 → 最后一次返回 confirmed 时直接拿到文档内容和回写状态。
🔒 TFS 回写不外露
TFS API 调用完全封装在 req-generation Skill 内部。FastAPI 不持有任何 TFS 连接逻辑，只做透传。Skill 可独立移植。
→ 透传链：PAT 不落地
tfs_pat 和 tfs_project 从 TFS-BUDDY → FastAPI message → DeerFlow → Skill → TFS API，全程内存传递，不持久化、不落盘。
✓ 一条 Thread 走到底
评估和生成共享 thread_id = {collection_name}-{work_item_id}。生成阶段直接从 Thread 历史提取已确认需求，不需要 API 传大段文本。
🛡 失败降级
Skill 回写 TFS 失败时，输出降级为 <doc_result>（仅文档内容）。FastAPI 返回 tfs_write_failed + document_content，TFS-BUDDY 可自行处理。
